The security fix in `env.ts` correctly uses a plain truthiness check on `import.meta.env.DEV`, which Vite statically replaces with `false` in production builds, dead-code-eliminating the `VITE_GROQ_API_KEY` literal. The `dist/` scan confirms no `gsk_` string survives into the bundle.

The coordinator lifecycle fix moves `historyId` from `useState` to `useRef`, collapsing `persistHistory`'s dep array to `[]` so the `LookupCoordinator` is created once per mount. The overlay integration test exercises the offline→AI replacement path and LOOKUP_COMPLETE clearing, confirming the fix holds end-to-end.

The `SettingsView` rewrite wires `loadAppSettings`/`saveAppSettings` correctly. The `HistoryView` fix properly gates `Clear all` behind `!savedOnly` and switches the per-item action to `Unsave`/`updateHistory` in the saved view. Both match the FEAT-003 acceptance criteria exactly.

New test files cover `parseAiJson` edge cases, full IndexedDB CRUD via `fake-indexeddb`, and OpenRouter/Gemini HTTP request shape. All three are in the node environment and don't affect existing test isolation.

The WordNet pointer stride fix (`i*2` → `i*4`) correctly reflects the 4-field structure of WordNet pointer entries; antonym coverage increased from 739 to 886 entries after regeneration.

One minor defect: a duplicate `await pruneHistory(historyLimitRef.current)` call in `Overlay.tsx` (lines 74–74) — the statement appears twice in a row. This is confirmed by the grep output. It causes `pruneHistory` to run twice per history save, which is functionally harmless (second call deletes nothing because the first already trimmed) but is unnecessary work.

### API key gate and key leak verification

`env.ts` wraps the `VITE_GROQ_API_KEY` read inside `if (import.meta.env.DEV)`. Vite statically replaces `import.meta.env.DEV` with the literal `false` in production builds, which causes the entire branch — including the `VITE_GROQ_API_KEY` string — to be eliminated by the bundler. The `dist/` scan returned no output, confirming no `gsk_` prefix survives.

The `FEAT-001` findings note that `=== true` strict comparison caused TS2367 under `strict: true`, so a plain truthiness check is used instead. This still achieves Vite dead-code elimination because `import.meta.env.DEV` in a `vite build` is replaced with `false`, making the condition `if (false)` which tree-shakes cleanly.

### Duplicate pruneHistory call in Overlay.tsx — confirmed

The grep output shows line 74 contains `if (historyLimitRef.current > 0) await pruneHistory(historyLimitRef.current)` twice in sequence. This is a copy-paste artifact. Each save triggers two prune passes; the second is a no-op since the list is already trimmed, but it opens an unnecessary IndexedDB round-trip on every lookup.

### Coordinator lifecycle fix

`historyIdRef = useRef<number | null>(null)` replaces the former `useState`. `persistHistory` now has `[]` as its dependency array, making it a stable function reference across renders. The coordinator `useEffect` depends on `[persistHistory]`, so it runs once on mount and cancels on unmount — the intended one-coordinator-per-mount lifecycle. `toggleSave` reads `historyIdRef.current` directly. The fix is complete and consistent.

### WordNet pointer parser

`scripts/lib/wordnet.mjs` now uses `i * 4` stride. WordNet 3.0 data files encode each pointer as four whitespace-separated tokens (`symbol offset pos source/target`), so the prior `i * 2` stride was reading wrong tokens for pointers after the first. The regenerated dictionary gained 147 antonym entries, and `tests/offline.test.ts` continues to pass.

### Test coverage additions

Three new test files land in `tests/`: `parse-ai-json.test.ts` (8 cases including nested braces and empty-string field omission), `history.test.ts` (9 cases covering full CRUD and `pruneHistory` edge cases via `fake-indexeddb`), and `providers.test.ts` (OpenRouter and Gemini request shape assertions using a mocked `globalThis.fetch`). FEAT-004 findings report 61 passed / 3 skipped, consistent with the expected baseline plus 19 new tests.
