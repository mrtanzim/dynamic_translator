# VocabFlow — Architecture

## Runtime
- Manifest V3 service worker (`src/background/service-worker.ts`)
- Content script entry (`src/content/content-entry.iife.ts`) — listens for the
  toggle message. It is built as an IIFE, because Chrome 130+ blocks the
  dynamic import the ESM bundle relied on.
- Shadow DOM host + React root lifecycle (`src/ui/mount.tsx`) — the host element
  is created and removed together with the React tree.
- React UI rendered inside the shadow root (`src/ui/Overlay.tsx`)
- The overlay stylesheet (`src/ui/styles.ts`) is injected into the shadow root,
  so the thin scrollbars cannot reach the scrollbars of the host page.

## Messaging
- `VOCABFLOW_TOGGLE` — service worker → content script, show/hide the overlay.
- `VOCABFLOW_AI_LOOKUP` — content script → service worker, proxies provider HTTP
  calls so the host page's CORS/CSP never blocks them (`src/providers/bridge.ts`).
- `VOCABFLOW_OFFLINE_LOOKUP` — content script → service worker, resolves a word
  against the offline dictionary. The dataset lives in the worker, so this is an
  asynchronous round trip (`src/providers/bridge.ts`, `src/providers/offline/`).
- `VOCABFLOW_SUGGEST` — content script → service worker, asks for the
  dictionary words that match a partially typed query. The type-ahead runs off
  the same dataset, so it is resolved in the worker as well.
- `VOCABFLOW_SEED` — content script → service worker, asks the worker to apply
  the first-run seed before the settings are read.

## Toggle without a page reload
The content script is declared for `<all_urls>`, so it is normally already
running in a tab. A tab that was open before the extension was installed or
reloaded never received it, and the toolbar click used to fall back to
`chrome.tabs.reload()` — which threw away the user's page state (video
position, form input, scroll offset).

The service worker now injects the content script on demand with
`chrome.scripting.executeScript()` and sends the toggle message again
(`src/background/content-script.ts` resolves the file name from the runtime
manifest, because the bundler emits a different one in development than in a
production build). If the page refuses extension scripts (`chrome://`, the Web
Store, a PDF viewer), the click is ignored rather than reloading the page.

The content script is idempotent: its state lives on the isolated world's
global object (`src/content/state.ts`), so a second injection into the same
frame reuses the existing listener instead of opening a second overlay.

## Storage
- `chrome.storage.local`
  - `vocabflow.overlay` — overlay position/size. The write is debounced by
    300 ms and flushed when the overlay closes.
  - `vocabflow.providers` — provider enable flag, model and API key (local only, never synced).
- IndexedDB `vocabflow` / store `history` — search history and saved words
  (`src/storage/history.ts`). One shared connection, a `saved` index for the
  saved-words list, and a single-transaction prune.
- `public/dictionary.json.gz` — offline dictionary dataset (read-only, shipped
  in the extension package). It is **not** part of the content-script bundle: the
  service worker fetches it at runtime, inflates it with `DecompressionStream`
  and keeps the indexes in memory for the worker's lifetime.
  The artifact is generated by `scripts/build-dictionary.mjs` (npm `build:dictionary`,
  also run automatically by `prebuild`).
- The dataset is **not** written by an AI model. It is assembled from two open
  datasets and a hand-written file:
  - `bn-en-dictionary` — the Bengali ⇄ English pairs of a Wiktionary dump
    (CC BY-SA 3.0): the Bengali meaning, the English definition and the part
    of speech
  - `wordnet-db` — Princeton WordNet 3.0: the synonyms, the antonyms and the
    example sentences
  - `src/dictionary/curated.json` — hand-written entries that win over the
    generated ones
- The dataset also carries the **romanization** of every Bengali spelling
  (`trans`, `transAlt`): the Latin-script spelling of a Bengali word
  ("বই" -> "boi"). It comes from the same Wiktionary dump, and it is what a
  learner needs to read a Bengali word, so the offline answer carries it
  without an AI provider. The romanization belongs to the *spelling*, not to
  the headword: "book" is written "বই", "কিতাব" and "বুক", and each spelling
  has its own Latin form.
- The AI providers never see the dataset. A provider request carries the
  query, the direction, the model and the key — nothing else. The offline
  lookup and the provider lookups are two independent paths that run at the
  same time.

## Search flow
The search field drives two things: the type-ahead and the lookup.

1. Every keystroke schedules a suggestion request (debounced by 120 ms, given
   up on after 1 s). The request is proxied to the service worker, which
   answers it from the dictionary index.
2. The lookup waits for the suggestions of the *current* query. A word that is
   only the beginning of a longer word (`cucu` → *cucumber*) is not looked up
   on its own: the suggestion is the better answer while the user is still
   typing, and a half-typed word must not be sent to the AI providers. A word
   that is in the dictionary itself is looked up as usual.
3. The suggestion list can be walked with the arrow keys, `Escape` closes it
   and `Enter` takes the highlighted suggestion. A query that is exactly one
   of the suggestions is searched as it was typed.

### Type-ahead ranking
The ranking is forgiving on purpose — a learner who cannot spell the word yet
still has to find it (`src/providers/offline/dataset.ts`):

1. the exact dictionary word,
2. a synonym or antonym, resolved to its headword,
3. every word that starts with the query,
4. every word within a small edit distance of the query (transpositions count
   as one edit),
5. every word that contains the query's letters in order.

The first three are answered from a sorted index (a binary search over the
prefix range), the last two scan the word list. The whole dictionary is
covered in about 4 ms, so the type-ahead does not slow the typing down.

## Lookup flow (`src/lookup/coordinator.ts`)
1. Normalize the query, allocate a monotonic `requestId`, mark it as the current one.
   Normalization is Unicode-aware (`\p{L}\p{N}\p{M}`) so that Bengali script
   survives — Bengali vowel signs are combining marks, not letters, and a
   naive `[^a-z0-9\s]` strip silently emptied the query.
2. Offline dictionary lookup → emit `LOCAL_RESULT` immediately (provisional).
   The lookup is proxied through the service worker, so it is asynchronous; a
   broken offline dictionary never breaks the AI lookups (best-effort, and it is
   given up on after 3 s).
3. Fan out to every enabled provider **concurrently**; each failure emits
   `LOOKUP_ERROR` for that provider only.
4. Stale-response guard: results whose `requestId` is no longer current are dropped.
5. Ranking:
   - The offline result is **provisional**: it is only shown while no provider
     has answered, and it never replaces a provider result.
   - The first valid provider result always replaces the provisional offline
     one, even when it carries fewer fields.
   - Later provider results only replace the accepted one when they are
     strictly better: completeness score first (Bengali meaning and Bengali
     example weigh most), then provider priority
     `groq > openrouter > gemini > offline`.
6. Emit `LOOKUP_COMPLETE` when all in-flight providers have settled.

### Identities
A lookup has two identities and they must not be mixed up:

- `requestId` identifies the **search action**. The offline result and the AI
  result of one search share it, so the history has exactly one row per search
  and the AI result updates that row instead of creating a second one.
- `query` is the **word the user typed**. It is what the history row stores,
  what the lookup direction is derived from and what the saved-words list is
  keyed on.

`word` is only a display value and is always the query as typed, so the header
does not change when the AI result replaces the offline one. The canonical
English headword the dictionary resolved is carried separately in `headword`.

## Directory structure
```
src/
  background/
    service-worker.ts     # MV3 service worker + provider/offline proxy
    content-script.ts     # resolves the content script file for on-demand injection
  content/
    content-entry.iife.ts # Shadow DOM host, toggle listener (built as an IIFE)
    state.ts              # per-frame state, shared by repeated injections
  lookup/coordinator.ts   # orchestration, request IDs, ranking
  providers/
    common.ts             # shared prompt, JSON parsing, fetch timeout
    bridge.ts             # content-script <-> service-worker contract
    groq/ openrouter/ gemini/  # provider implementations
    offline/
      dataset.ts          # columnar dataset + runtime indexes + type-ahead
      loader.ts           # service-worker fetch + gunzip + index
      index.ts            # content-side offline lookup + suggestion client
  shared/types.ts         # LookupResult, LookupEvent, View
  storage/
    settings.ts           # provider settings + API keys
    app-settings.ts       # overlay preferences (autoSpeak, historyLimit, theme)
    history.ts            # IndexedDB history / saved words
    seed.ts               # first-run provider seed
  ui/
    mount.tsx             # Shadow DOM host + React root lifecycle
    Overlay.tsx           # React overlay (search, menu, views)
    views/                # Providers / History / Settings / About
scripts/
  build-dictionary.mjs    # generates public/dictionary.json.gz
  lib/bengali.mjs         # shared Bengali normalization
tests/                    # vitest: coordinator, offline dictionary, overlay,
                          # history, providers, service worker, content script
```

## Data models
- `LookupResult { word, query, headword?, bengaliMeaning?, englishDefinition?, transcription?, pronunciation?, synonyms?[], antonyms?[], exampleEn?, exampleBn?, partOfSpeech?, source, requestId, timestamp }`
  - `transcription` is the word in the other script (an English word in
    Bengali script, a Bengali word in Latin script) and `pronunciation` is an
    IPA or respelling guide. The AI provider answers both; for a Bengali
    query the offline dictionary supplies the Latin-script spelling from the
    dataset.
- `LookupEvent = LOCAL_RESULT | AI_RESULT | LOOKUP_COMPLETE | LOOKUP_ERROR`
- `HistoryEntry { id?, query, direction, result, source, timestamp, saved }`
- `ProviderSettings { groq, openrouter, gemini: { apiKey, enabled, model } }`
- `OverlayState { x, y, w, h }`
